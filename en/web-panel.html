Moderation

Web panel

Run your server from a browser. Players by game mode, live chat, punishments and feature switches, with access tied to each staff member's in-game rank.

The web panel lets your staff manage the server from a browser or a phone, without joining the game. They see who is online in every game mode, read the chat live, check a player's history, mute, kick, ban, and (if you allow it) turn features on and off.

The panel has no accounts and no passwords of its own. A staff member proves who they are from inside the game, and the panel can do exactly what that person can already do with commands, nothing more. It ships off.

#Turning it on

Open config.yml, set Enabled: true and restart the server.

yaml
Panel:
  Enabled: false
  Bind: "127.0.0.1"
  Port: 8765
  Public_Url: ""
  Session_Minutes: 120
  Allow_Offline_Actions: false
  Allow_Console: false
  Trust_Forwarded_For: false
  Allowed_IPs: []
  Lock_Session_To_IP: true
  Discord_Login: true
  Discord_OAuth:
    Client_Id: ""
    Client_Secret: ""
  Service_Token: ""
  Textures:
    Download: false
Option Default What it does
Enabled false Starts the panel. Needs a restart
Bind 127.0.0.1 Which address of the machine the panel listens on. See Opening it to your staff
Port 8765 The port. Pick any free one
Public_Url empty The address shown to staff with their code, for example https://panel.example.com
Session_Minutes 120 How long a session lasts before a new code is needed (5 to 1440)
Allow_Offline_Actions false Lets staff with chatalyst.panel.offline act while they are not in game
Allow_Console false Lets staff with chatalyst.panel.console run any console command
Trust_Forwarded_For false Read the visitor's real address from your own reverse proxy
Allowed_IPs empty If not empty, only these addresses can load the panel at all
Lock_Session_To_IP true A session only works from the address that opened it
Discord_Login true Staff can get their code by Discord private message instead of joining the game
Discord_OAuth.Client_Id empty The Application ID of your Discord application
Discord_OAuth.Client_Secret empty The Client Secret from the OAuth2 tab; when both are set, the "Sign in with Discord" button appears
Textures.Download false Real item icons, block textures and models, armor and the health and hunger icons. See Live view

#Signing in

  1. The staff member joins the server and runs /chatalyst panel.
  2. They get a code such as K7QM-4XWP in chat. Clicking it copies it. It lasts 2 minutes and works once.
  3. They open the panel address and type the code.

#Without joining the game

Recommended — "Sign in with Discord" (OAuth2): The staff member clicks Sign in with Discord on the sign-in page, Discord asks them to authorise (only the identify permission: Chatalyst only reads who they are, nothing more), and they go straight in with the Minecraft account they linked with /discord link. If their Discord is not linked, the page tells them to link Discord and Minecraft first with /discord link. If it is linked but that account does not have chatalyst.panel, it tells them that as well. The Chatalyst bot does not need to be running and their Discord does not need to accept private messages; only the link has to exist.

To turn it on:

  1. In https://discord.com/developers/applications, open your application (the bot's own application works) and go to OAuth2.
  2. Copy the Client ID and Client Secret to Panel.Discord_OAuth.
  3. Under Redirects, add <Public_Url>/api/login/discord/callback exactly, for example https://panel.example.com/api/login/discord/callback (Public_Url must be the address staff open in their browser).
  4. Run /chatalyst reload or restart the server. The secret is a password: do not share it.

Code by private message (kept when Discord_OAuth is empty): If the Chatalyst Discord bot is running and the staff member has linked their account (/discord link), on the sign-in page, under Not in the game?, they type their Minecraft name and the bot sends the one-time code to their Discord by private message. Only an account that is linked and has chatalyst.panel gets a code. The page answers the same thing whatever name is typed, so it cannot be used to find out who is staff, and each account can ask once a minute. Their Discord must accept private messages from members of your server.

Discord_Login: false turns both ways off. Every sign-in and every failed attempt is written to the activity log.

If you run your own Discord bot instead of the Chatalyst one, it can do the same: from the console or RCON, chatalyst panelcode <discord-id> writes PANEL OK <uuid> <player> <code> to the server log for the Minecraft account linked to that Discord user (or PANEL DENIED <reason>), and your bot hands the code over in private.

Signed in this way and not in game, a staff member can watch everything their rank allows; to act they still need Allow_Offline_Actions and chatalyst.panel.offline.

The player gets a chat notice every time a session is opened with their account, with the address it came from. /chatalyst panel logout closes their sessions at once.

#Finding your way around

The overview opens with the numbers that matter right now (players, TPS, uptime, open reports) and two charts of the last hour: players online and TPS. A dip in the TPS line tells you the server stuttered even if you were not looking at the time. The charts fill in during the first minutes after a restart, and they are kept in memory only. Staff who can see the history also get the latest sanctions on that page.

A few things work everywhere in the panel:

  • Quick search: press Ctrl + K (or the search button at the top) to jump to any section or to a player. Type a name that is not online and it offers to look that player up.
  • Menu counters: Alerts and Reports show how many are waiting, so you do not have to open them to find out.
  • Your session: click your name at the top to see your rank, whether you can act or only read, and when the session ends. You can sign out from there.

Sanctions can be narrowed down by type (bans, mutes, warnings, kicks) and searched by player, staff member or reason. Export CSV downloads what you are looking at, up to the 1,000 most recent rows, ready for a spreadsheet.

#Who sees what

The panel reads the same permissions the game uses, so you set it up once in LuckPerms. A helper who can only mute sees a mute button and nothing else. Buttons a rank cannot use are not shown.

Permission Default In the panel
chatalyst.panel op Sign in. See players and the live chat
chatalyst.command.kick op Kick
chatalyst.command.mute op Mute and unmute
chatalyst.command.ban op Ban, temporary ban and unban
chatalyst.command.warn op Warn
chatalyst.command.freeze op Freeze and unfreeze
chatalyst.command.history op A player's history and the server-wide punishment list
chatalyst.staff.notes op Staff notes on a player
chatalyst.channel.staff op Write in the staff channel
chatalyst.command.broadcast op Send a broadcast
chatalyst.panel.live op Open a player's live view: the map around them and their status
chatalyst.command.invsee op See the inventory in the live view
chatalyst.panel.alerts op See the moderation alerts: x-ray, autoclick, exploits, spam, filtered words
chatalyst.report.manage op See open reports, take them and close them
chatalyst.panel.features op Turn features on and off
chatalyst.panel.audit op See the activity log. Meant for the owner
chatalyst.admin op Reload the configuration
chatalyst.panel.offline nobody Act while not in game (also needs Allow_Offline_Actions)
chatalyst.panel.console nobody Run console commands (also needs Allow_Console)

A typical setup:

text
/lp group helper permission set chatalyst.panel true
/lp group helper permission set chatalyst.command.mute true
/lp group mod permission set chatalyst.command.kick true
/lp group mod permission set chatalyst.command.ban true
/lp group mod permission set chatalyst.command.history true
/lp group admin permission set chatalyst.panel.features true

Rank protection works as in game: a moderator cannot punish someone of a higher rank from the panel, because the panel runs the moderator's own command.

#Losing a rank

Permissions are checked on every request, not only at sign-in.

  • If the staff member is in game, the panel uses their permissions of that moment. Remove a permission and the button stops working on the next click.
  • If they are not in game, the panel asks LuckPerms every 30 seconds. Take the rank away and their session closes even if they never come back.
  • A banned account loses its session.

Note

Without LuckPerms the panel cannot check a player who is not in game. Their session still ends on its own after Session_Minutes, and it is read-only unless you turned on Allow_Offline_Actions.

#Live view

From a player's record, Live view shows what that player is doing right now without you joining the server: a top-down map of the blocks around them (24 blocks each way, refreshed every 2 seconds), the player as an arrow pointing where they look, and who or what is near them. Next to it are their world and coordinates, health, hunger, level, game mode, ping and active effects, and, with chatalyst.command.invsee, what they hold, wear and carry.

The view has three modes. First person shows what the player sees, with the item they hold in the corner of the screen. Around lets you orbit the camera: the player is drawn as the real model with their skin, the armor they wear and what they carry in each hand, and so are the players near them. Map is the top-down view. Blocks keep their real shape (chains, lanterns, fences, stairs, slabs, torches), the sky follows the time of day in that world, and a line traces where the player walked in the last 90 seconds.

It runs in real time: the player's position and where they look are refreshed five times a second and smoothed in between, and a block they place or break shows up in under a second. Over the picture you get their coordinates, heading, speed and what they are looking at; an amber tag appears when they move faster than walking allows or stay in the air too long. Those are hints for you to look closer, not a verdict. You can pause the view, go full screen, and freeze, mute, warn, kick or ban from right under it.

Next to it, health, hunger and experience are drawn the way the game draws them, and the inventory uses the game's own layout: armor and off hand on one side, the backpack and the hotbar with the slot in use marked. Hover an item to read its name, enchantments, lore and durability.

There are three ways to look, with a switch above the picture:

  • First person shows the world in 3D from the player's own eyes, turning as they turn, like spectating them.
  • Around is the same 3D world with the camera circling the player. Drag to turn it and use the wheel to zoom.
  • Map is the top-down view.

Other players appear with their skin's face, and animals and monsters with a picture, so you can tell at a glance who and what is there.

#Real textures

Out of the box the 3D view and the inventory use flat colours and short codes. To see the real block textures and item icons, set this in config.yml and restart:

yaml
Panel:
  Textures:
    Download: true

Note

The textures belong to Mojang, so Chatalyst does not ship them. With Download: true the plugin downloads the official Minecraft client for your version once, from Mojang's servers to your machine, unpacks the textures into plugins/Chatalyst/panel-textures and deletes the rest. Turn it on only if you accept the Minecraft EULA. It needs about 40 MB of download and a few MB on disk.

When the player is under a roof (a cave, the Nether, inside a build) the map shows the floor at their level instead of the surface. Areas that are not loaded show as black; the panel never loads chunks. It works for players on the server the panel runs on, and vanished staff stay hidden from anyone who cannot see them in game.

#Alerts and reports

Alerts lists what the detectors flagged, newest first: x-ray, autoclick, exploits, spam, filtered words and chat rules. Each one names the player and what was seen, with a button to open their record or go straight to their live view. It is the same thing staff see in game; nothing new is detected for the panel. Alerts are kept in memory, so the list starts empty after a restart.

Reports lists the open player reports. A staff member can take one, release it, and resolve or reject it with a closing note, exactly as with /reports in game.

When a staff member acts from outside the game, a target who is protected against that punishment (chatalyst.bypass.mute, chatalyst.bypass.ban and so on, or an operator) is refused, just as in game.

#Using it from your own panel

If you already run a panel or a bot on the same machine, it can use this one's API instead of making your staff open two panels. Set a long random value in Service_Token and send it in the X-Chatalyst-Service header, with the staff member's Minecraft UUID in X-Chatalyst-Actor. The call can do exactly what that player's permissions allow, and every action is written to the activity log under their name.

It only works from 127.0.0.1, and only with a token of 32 characters or more. Acting while the staff member is not in game also needs Allow_Offline_Actions: true.

#Staff service hours

Turn on Staff_Activity.Enabled and Chatalyst counts, minute by minute, how long each staff member is online doing something and how long they are AFK. Moving, chatting and using commands all count as active, so a helper answering questions while standing still is still working; three minutes with none of that is AFK. It also counts time in staff mode and the sanctions each one gave that day.

yaml
Staff_Activity:
  Enabled: false
  Permission: "chatalyst.channel.staff"   # who counts as staff

Owners (chatalyst.panel.audit) see it in the Team view of the panel, for today, the last 7 days or the last 30. The same data is kept in plugins/Chatalyst/staff-activity.json (last 45 days, times in seconds), a plain file on purpose so your own tools can read it.

#Activity log

Everything that happens in the panel is written down: who signed in and from which address, failed sign-in attempts, who signed out or lost their session, every action taken, every feature switched, every console command, and whose live view was opened by whom.

Staff with chatalyst.panel.audit see it in the panel under Activity. Give that permission only to the owner rank. The log is kept in plugins/Chatalyst/panel-audit.log, so it survives restarts, and the same lines go to the server console with the [Panel] prefix.

#In game or out of game

While the staff member is also connected to the server, every action runs as their own command and the reply goes to their in-game chat.

When they are not connected, the panel is read-only by default: they can watch players, chat and history, but not act. To let trusted ranks act from outside, set Allow_Offline_Actions: true and give them chatalyst.panel.offline.

Warning

Actions taken from outside the game run as the console. Protected players and operators are still refused, but the finer rank order (a moderator not touching an admin) is not checked. Give chatalyst.panel.offline only to ranks you trust with that.

#Opening it to your staff

With the default Bind: "127.0.0.1" the panel only answers on the server machine itself. That is the safe starting point: nobody on the internet can reach it.

To let staff open it from their own devices you have three options, from safest to simplest.

#Behind an HTTPS reverse proxy (recommended)

Keep Bind: "127.0.0.1" and let a web server on the same machine publish it with HTTPS. With Caddy this is the whole file:

text
panel.example.com {
    reverse_proxy 127.0.0.1:8765
}

Then set:

yaml
Panel:
  Public_Url: "https://panel.example.com"
  Trust_Forwarded_For: true

A Cloudflare Tunnel or nginx works the same way. No extra port has to be opened in the firewall beyond 443.

#Through a VPN

If your staff share a VPN (WireGuard, Tailscale), bind the panel to the VPN address of the machine and only people inside the VPN can reach it:

yaml
Panel:
  Bind: "10.8.0.1"
  Allowed_IPs: ["10.8.0."]

#Directly on a port

Set Bind: "0.0.0.0" to listen on every address of the machine, and open the port (TCP 8765 by default) in your firewall or in your host's panel. Staff then open http://your-server-ip:8765.

Warning

This is plain HTTP: the sign-in code and the session travel unencrypted. Use it only for testing or together with Allowed_IPs. On shared Minecraft hosting you can usually only use ports the host assigns you; ask them for an extra port and put it in Port.

#How it is protected

  • No passwords. There is nothing to leak or reuse. Only someone who is in game with the right rank can get a code.
  • One-time codes. A code lasts 2 minutes, works once, and asking for a new one cancels the old one.
  • Guessing is blocked. Eight wrong codes from one address lock that address out for a minute.
  • Sessions are tied to the address. A copied session cookie does not work from another network. The cookie cannot be read by scripts and is never sent to other sites.
  • Other websites cannot act for you. Every change needs a header a foreign page cannot send, and the request must come from the panel itself.
  • Optional address list. With Allowed_IPs, anyone else cannot even load the sign-in page.
  • Everything is logged. Each sign-in and each action is written to the server console with the staff member's name and address, prefixed with [Panel].
  • The dangerous parts are off. Console access and acting from outside the game need both a config switch and a permission nobody has by default.

#Commands

Command What it does
/chatalyst panel Gives you a one-time code to sign in. /chatalyst web does the same
/chatalyst panel logout Closes your panel sessions

#Troubleshooting

What you see Why
"The web panel is off" Panel.Enabled is false, or the port was taken at startup. Check the console for a [Panel] line
The page does not load from outside Bind is still 127.0.0.1, the port is closed in the firewall, or your address is not in Allowed_IPs
"That code is wrong or has expired" More than 2 minutes passed, it was already used, or a newer code replaced it
Signed out after switching from Wi-Fi to mobile data Lock_Session_To_IP did its job. Ask for a new code
Buttons are missing That rank lacks the permission for them
"Join the game to act" You are not connected to the server and offline actions are off
