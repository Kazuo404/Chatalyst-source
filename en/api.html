Developers

Developer API

For plugin developers - the Chatalyst service, the titles and achievements API, its events and the PlaceholderAPI values.

This page is for developers who want to connect their own plugin to Chatalyst. Server owners do not need it.

Chatalyst offers a versioned service, a separate compile-time API jar, events that fire after data is saved, and PlaceholderAPI values.

#Getting the API

Install the normal Chatalyst jar on the server. Keep the smaller Chatalyst-API-<version>.jar only in your project.

  1. Copy the API jar into your project's libs/ folder.
  2. Declare it as compileOnly (Gradle) or provided (Maven), so it is never bundled.
  3. Add Chatalyst to depend (required) or softdepend (optional) in your plugin.yml.
  4. Get ChatalystApi in onEnable().
kotlin
dependencies {
    compileOnly(files("libs/Chatalyst-API-1.0.0.jar"))
}
yaml
depend: [Chatalyst]
java
ChatalystApi api = ChatalystApi.get()
    .orElseThrow(() -> new IllegalStateException("Chatalyst is unavailable"));
TitlesApi titles = api.titles();

TitleProfile profile = titles.profile(player.getUniqueId());
titles.equipped(player.getUniqueId()).ifPresent(title ->
    getLogger().info(title.displayName()));

Note

ChatalystApi.API_VERSION is independent from the plugin version.

#Titles and achievements service

Area Operations
Read snapshots catalog, catalogFor, find, equipped, isUnlocked, profile, collections, ranking
Player changes equip, unequip, grant, revoke, with typed results and actor, cause and reason context
Progress progress and evaluate return futures and run on the player's entity scheduler (Folia included)
Catalog administration create, update, duplicate, delete, collection presentation and catalog settings

All returned objects are immutable snapshots. Secret locked titles have no definition in catalogFor, and hidden locked titles are left out.

#Handle typed results

Treat SUCCESS and NO_CHANGE as success, and log the rest with their message:

java
TitleMutationResult result = titles.equip(
    player.getUniqueId(), "champion", TitleMutationContext.api());

if (!result.successful()) {
    getLogger().warning(result.status() + ": " + result.message());
}

#Evaluate progress safely

java
titles.evaluate(player).thenAccept(result -> {
    if (result.successful() && !result.unlocked().isEmpty()) {
        getLogger().info("New titles: " + result.unlocked().size());
    }
});

#Events

Title events fire only after the change is saved. They carry a TitleMutationContext with the cause, the optional actor and the reason.

Event When
TitleUnlockEvent A new permanent or seasonal unlock is stored.
TitleEquipEvent A title becomes the player's selection.
TitleUnequipEvent The selection is removed, also when the title is revoked.
TitleRevokeEvent An unlock is removed.
TitleCollectionCompleteEvent A new unlock completes a collection.
TitleCatalogChangeEvent A title is created, updated, duplicated or deleted.

ChannelMessageEvent, ChannelSwitchEvent, RuleMatchEvent and RuleReplaceEvent are also available in dev.chatalyst.api. If an event is asynchronous, schedule world or entity access on the right scheduler.

java
@EventHandler
public void onTitleUnlock(TitleUnlockEvent event) {
    getLogger().info(event.getPlayerId() + " unlocked " + event.getTitle().id());
}

#Parties for your plugin

Add your own group to Type: PARTY channels. Register it in onLoad(), because Chatalyst reads its channels while it enables. If you register later, run /cht reload.

java
@Override
public void onLoad() {
    if (getServer().getPluginManager().getPlugin("Chatalyst") != null) {
        ChatalystParties.register("myplugin-claim", player -> {
            String claim = claimIdOf(player);
            return claim == null ? List.of() : List.of(claim);
        });
    }
}

Return every group the player belongs to. Two players share the channel when their groups overlap, and an empty list means no group. It runs on the player's own thread about every two seconds, so keep it fast. Add softdepend: [Chatalyst] to your plugin.yml, then use it in chat.yml:

yaml
Channels:
  List:
    claims:
      Type: PARTY
      Party: myplugin-claim
      Format: chat

#Checks

ChatalystApi.get() also answers these, from any thread:

Method Answers
isMuted(UUID) The player cannot chat, by a Chatalyst mute or another mute plugin.
isChatLocked() Chat is locked with /chatlock.
channelExists(String) That channel is loaded.

#Chat events

All of these can be cancelled.

Event When
PlayerMuteEvent Before Chatalyst mutes a player. getUntil() is -1 for a permanent mute.
PlayerMentionEvent Before a mentioned player is notified. Cancelling skips the sound.
PrivateMessageEvent Before a private message is delivered.
