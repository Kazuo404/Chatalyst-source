Common problems

The problems server owners run into most often, why they happen and how to fix each one.

Something not working as expected? Find the symptom below. Each entry says why it happens and what to change. If yours is not here, run /cht doctor first: it checks your configuration and shows the exact line of any mistake.

#Chat looks like vanilla or like another plugin

Another chat plugin is formatting the chat after Chatalyst, or Chatalyst formatting is off.

  1. Check Chat.Enabled: true in chat.yml.
  2. Use only one plugin that formats chat. If you keep EssentialsX Chat or a similar plugin, remove it or turn its formatting off.

See Compatibility & conflicts for the details.

#/msg says private messages are disabled

The owner switch is off. Set it back in players.yml and reload:

yaml
Private_Messages:
  Enabled: true

Mail (/inbox) is a separate system and has its own switch.

#Ranks show no prefix or no color

  • The default format uses %luckperms_prefix%, which needs PlaceholderAPI with the LuckPerms expansion. Without PlaceholderAPI, change it to {player_prefix} in formats/chat.yml.
  • {rank_color} takes the first color of the prefix. Give your LuckPerms prefix a color, for example &c[OWNER]. Both & codes and MiniMessage work.

#A command answers with another plugin's message

Two plugins registered the same command and the other one won. On startup Chatalyst warns about commands "answered by another plugin". Decide which plugin should own each command:

  • To let the other plugin keep it and stop the warning, add the label to Commands_Owned_Elsewhere in config.yml.
  • To make Chatalyst answer, remove or disable the command in the other plugin. Chatalyst's version is always reachable as /chatalyst:<command>.

See Compatibility & conflicts.

#The delete-message [x] does nothing

Deleting works for lines that Paper delivered as signed chat. A line that arrived without a usable signature, or as a system message (for example a translated line), cannot be removed from players' screens. Mutes and the anti-spam still work; /clearchat is the fallback.

#Players see every command when typing /

Since Minecraft 1.13 the game builds that list on the player's side, so no plugin can require a minimum number of letters. Chatalyst already hides commands players have no permission for, plus plugin-info commands, with the tab-complete filter (Tab_Complete in chat.yml).

#No name above players' heads

The vanilla name is hidden (by TAB or by the fancy nametag) but the fancy nametag is not running. Check Nametag.Fancy.Enabled: true in nametag.yml. It is a different setting from the classic Nametag.Enabled. See Tab list & nametags.

#Discord messages do not reach the game

Check the bot settings in integrations.yml: Discord.Enabled: true, the bot token, guild and channel ids, and that Message Content Intent is turned on in the Discord developer portal. Then run /cht doctor discord. See Discord bot.

#The config broke but the server started

That is on purpose. When a YAML file cannot be read, Chatalyst saves a copy as config-broken-<date>.yml, keeps your license key, starts with a clean file and prints the exact line of the error. Fix the copy, paste your changes back and run /cht doctor.

#A feature does nothing

Most extras ship off. Run /cht features: it lists what is off and the exact setting to change. See Turn on extras.

#Still stuck

Ask on Discord (https://discord.gg/uWTNeBmMT3). Include your server software and version, the Chatalyst version and the full startup log.
