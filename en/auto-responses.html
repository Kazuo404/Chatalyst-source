Optional extras

Auto responses

A chat bot that answers common player questions automatically, in each player's language, and only offers what your server really has.

New players ask the same questions again and again: how do I make money, how do I claim land, where is my purchase. The auto-response bot answers them for you. When a message looks like a known question, the bot replies a moment later with the answer you wrote, in the player's own language.

It understands how people really type. "komo gano din3ro!!!" and "how do i make money" reach the same answer. And its answers can adapt to your server: a reply about money only mentions /jobs if /jobs exists, and only mentions the market if your market is on.

Chatalyst ships with 44 ready-made answers in English and Spanish (money, balance, private messages, mail, channels, reports, Discord, ranks, homes, warps, land claims, kits, voting, PvP, lag and more). Edit, delete or add your own in bot.yml.

#Turning it on

It is an optional extra and ships off. Set Enabled: true and run /cht reload. The global settings are at the top of the Auto_Responses section in bot.yml:

yaml
Auto_Responses:
  Enabled: false
  Bypass_Permission: "chatalyst.bypass.autoresponse"
  Auto_Language: true
  Language: "en"
  Private_Questions: true
  Private_Questions_Mode: explicit
  Precision:
    Require_Question: true
    Max_Words: 14
    Question_Words: []
  Player_Cooldown_Seconds: 60
  Global_Cooldown_Seconds: 10
  Delay_Ticks: 15

Warning

Remember to turn the bot on: Enabled: false is the default. Players and ops can all use it.

Option Default What it does
Enabled false Turns the whole bot on or off
Bypass_Permission chatalyst.bypass.autoresponse Messages from players with this permission never trigger the bot. Nobody has it by default, ops included: give it to staff if you want them silenced
Auto_Language true Each player gets the answer in their client language (English or Spanish)
Language en Fixed language (en or es) used when Auto_Language is false
Private_Questions true The answer goes only to the asker, and a clear question is taken out of public chat so it stays clean
Private_Questions_Mode explicit explicit hides a message only when a trigger matched and it is really a question, or almost all of it is the trigger. With a keyword match the message stays in chat. all hides on any match
Precision.Require_Question true Triggers and keywords need the message to look like a question. A trigger phrase that makes up at least half of the message also counts
Precision.Max_Words 14 Longer messages are treated as conversation (0 = no limit). Regular expressions ignore this limit
Precision.Question_Words [] Extra words that open a question, on top of the built-in English and Spanish ones
Player_Cooldown_Seconds 60 Default wait before the same player gets the same answer again
Global_Cooldown_Seconds 10 Default wait before an answer the whole server sees is repeated. Private answers do not use it
Delay_Ticks 15 Short pause before answering, so it feels natural (20 ticks = 1 second)

#Writing a response

Each entry under Responses needs at least one way to detect the question and one answer. This one comes from the real file:

yaml
    ignore-player:
      Keywords:
        - "ignor|=block|bloquear|bloqueo|bloquea|mutear|callar|molest|acos"
        - "jugador|player|persona|alguien|user|chico|tipo|como|komo|how|puedo|can"
      Reply:
        - "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>Ignore someone with <#E0AAFF>/ignore <player><#C0B3D9>: you stop seeing their chat and private messages. Run it again to unignore."
      Reply_es:
        - "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>Ignora a alguien con <#E0AAFF>/ignore <jugador><#C0B3D9>: dejas de ver su chat y sus privados. Ejecutalo otra vez para dejar de ignorarlo."
      To: player
Key What it does
Triggers A phrase, or a full regular expression with the regex: prefix. Write both languages. A phrase needs the message to be a question or to be mostly that phrase; a regular expression always counts
Keywords Flexible detection. Each line is a group of words separated by a vertical bar; the response fires when the message contains one word from every group
Reply / Reply_es The answer lines for English and Spanish clients. If one is missing, the other is used. {player} is the asker's name
If_Plugin Alternative replies used only when a given plugin is installed
Smart An answer built from parts that depend on what your server has (see below)
To player answers only the asker; everyone sends it to the whole server, each viewer in their language
Require_Question Overrides Precision.Require_Question for this response
Priority Adds or takes away points when several keyword responses match. Use a negative number on generic answers
Player_Cooldown_Seconds, Global_Cooldown_Seconds, Delay_Ticks Override the global values for this response

A response fires if any of its detections matches. Before matching, the message is normalized: lowercase, no accents, leet speak undone (din3r0 becomes dinero), stretched letters shortened (holaaaa becomes hola), apostrophes removed (what's becomes whats) and punctuation turned into spaces.

Tip

In Keywords, use short word stems like gan, consig or earn. A stem catches every form of the word: gano, ganar, ganando.

#Exact words

A stem also catches anything else that starts the same way: ban matches banco, and spawn matches spawner. Put = in front to match the whole word only: =ban, =spawn. Words of one or two letters always match whole, and a keyword with a space is matched as a phrase.

#When several responses match

  • A trigger beats any keyword match. Between triggers, the one covering the most text wins.
  • Between keyword responses, the longest word that matched counts, and the first group counts double. Put the topic in the first group and the intent in the second.
  • Priority adjusts that score. The shipped how-to-buy uses -5, so "como compro un kit" reaches the kits answer.
  • On a tie, the first response in the file wins.
  • If the winner is on cooldown the bot stays silent. It does not fall back to the second best.

#Smart replies

A smart reply is built from parts, and each part is only said if what it Needs is available right now. If no part applies, the Unavailable line is used instead. A part with no Needs is always said.

yaml
    how-to-money:
      Keywords:
        - "dinero|plata|money|coin|moneda|lana|feria|billete|cash|guita|varo|bucks|dosh|moolah|dough|rich|rico"
        - "gan|consig|hag|hac|sac|junt|farm|earn|make|get|neces|need|wanna|gimme|grind|start"
      Smart:
        Intro: "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>Hi <#FBF2FF>{player}<#C0B3D9>, ways to earn money here:"
        Intro_es: "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>Hola <#FBF2FF>{player}<#C0B3D9>, formas de ganar dinero aqui:"
        Parts:
          - Needs: "command:jobs"
            Text: "<#C0B3D9>• Work a job with <#E0AAFF>/jobs<#C0B3D9>."
            Text_es: "<#C0B3D9>• Trabaja un empleo con <#E0AAFF>/jobs<#C0B3D9>."
          - Needs: "market"
            Text: "<#C0B3D9>• Sell your own items on <#E0AAFF>/market<#C0B3D9>."
            Text_es: "<#C0B3D9>• Vende tus propios items en <#E0AAFF>/market<#C0B3D9>."
        Unavailable: "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>There's no money system enabled on this server yet."
        Unavailable_es: "<#7B68A0>[<#B56CFF>Bot<#7B68A0>] <#C0B3D9>Aun no hay un sistema de dinero activo en este servidor."
      To: player

What a part can need:

Needs Available when
command:<name> That command exists on the server, e.g. command:jobs
plugin:<Name> That plugin is installed and enabled (name as shown in /plugins)
pm Private messages are on
mail Mail is on
market / trade The market / direct trading is on
channels Chat channels are on
announcements The announcer is on
economy / baltop An economy plugin is present / the money ranking is on
store / ranks Item deliveries / the rank storefront are on
rent Perk rentals are on, with an economy and at least one offer
discordlink Discord account linking is actually usable

In reply texts, {ranks_command} is replaced with whatever your storefront command is called (see store). Availability is checked each time the bot answers, so turning a feature on or off applies right away.

#How it fits with the rest of the chat

The bot only answers messages that got through: if the rules engine or the anti-spam blocked the message first, the bot stays silent. The swear filter and logging still apply to the question as usual. Commands never reach the bot, and it does not read its own answers.

Each answer is written to the chat log under [BOT], with the response that fired and whether it came from a trigger or from keywords. Read it to tune bot.yml against what players really ask.

#Updating from an older version

Installed servers keep their own bot.yml, so new answers and improved keywords are not added on their own. The engine improvements apply right away. To get the new keywords, compare your file with the one in the new jar, or delete bot.yml to get a fresh copy if you never edited it.

#Limits

  • Replies come in English and Spanish only. Players with other client languages get the English reply.
  • The language follows the client, not the question. A player with an English client who asks in Spanish gets the English reply.
  • The bot answers questions in chat; it does not hold a conversation or remember what a player asked before.
  • Detection is based on words and patterns you write. If players ask in a way none of your triggers cover, add a trigger or a keyword.
