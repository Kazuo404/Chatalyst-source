Moderation

Staff suite

An optional, menu-driven moderation toolkit with bans, kicks, freezes, connection bans, vanish, staff mode and inventory checks.

The staff suite gives your team everything to handle a problem player from one menu: ban, kick, freeze, vanish, check inventories and read a player's history. Staff do not need to memorize commands; /staff opens a dashboard with buttons for each action.

It ships off, so Chatalyst never fights a staff plugin you already use. Turn it on only if you want Chatalyst to be your moderation plugin.

#Turn it on

In moderation.yml:

yaml
Staff_Moderation:
  Enabled: true

Then restart the server or run /cht reload. While it is off, none of its commands are registered.

#What it includes

Tool Commands
Dashboard /staff opens the menu: player list, reports, frozen players and tools.
Punishments /kick, /warn, /ban, /tempban, /unban. Reasons come from presets or are typed privately.
Connection bans /banip, /unbanip: block the account and its connection, kick shared accounts and ban new alts.
Freeze /freeze, /unfreeze: stop a player for a review. Leaving during the review gives a permanent ban.
Vanish and staff mode /vanish: invisible, silent and unable to change the world while watching.
Inspection /invsee, /echest, /seen, /check (history, possible alts, notes).
Notes /note: private notes about a player, shared by the team.
Teleport /tpto, /tphere.

Every tool also has Spanish aliases. The full list with permissions is in Commands; chatalyst.staff.* gives all of them.

#Who owns /ban, /kick and /vanish

With the suite on, Chatalyst takes the plain command names even if another plugin registered them first, so its tools are the ones that answer. If you turn the suite off again, the other plugin gets them back.

yaml
  Command_Priority: true
  Exempt_Ops: true
  • Command_Priority: false only takes names no other plugin uses. The /chatalyst:ban form always works.
  • Exempt_Ops: true means operators can never be punished or frozen. Set it to false on small servers where trusted players keep OP.

#Reasons without typing

The menus offer preset reasons, so staff click instead of type. "Custom reason" is always there too: the staff member types it in chat and it is captured privately. Edit the lists in moderation.yml:

yaml
  Reason_Presets:
    - "Hacks / modified client"
    - "X-Ray"
    - "Toxicity / harassment"
    - "Advertising"
    - "Griefing"
    - "Punishment evasion"

Reason_Presets_es holds the Spanish versions.

#Possible alt accounts

/check can show names that joined from the same connection. For privacy, the IP itself is never stored, only a hash of it. Remember that siblings or a shared café also share a connection: it is a clue, not proof. Only staff with chatalyst.staff.alts see it.

#Accountability

Every punishment goes into the player's history, shown by /check and the history menu. With Staff security on (Staff_Security.Enabled in moderation.yml), sensitive staff commands are also copied to the console and to the private staff Discord channel. See Spy & logs.

Tip

The suite includes more optional guards in moderation.yml: Staff_Item_Audit (items staff spawn), Item_Watch (valuable items in inventories) and Anti_Exploit. Each has its own Enabled switch.
