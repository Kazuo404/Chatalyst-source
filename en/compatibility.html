Compatibility & conflicts

Which servers and versions Chatalyst supports, how it shares the chat with other plugins, and how to solve command conflicts.

This page answers two questions: will Chatalyst run on my server, and how does it get along with the plugins I already have. Most servers need to change nothing. Read on if another plugin also formats chat or uses the same command names.

#Supported servers

Supported
Server software Paper, Purpur and Folia (see its limits). Spigot is not supported.
Minecraft 1.21.1 to 26.3.
Java Java 21 for 1.21.1 to 1.21.11. Java 25 for 26.1 and newer.
Proxies Velocity and BungeeCord, see Proxy & Redis networks.
Bedrock players (Geyser) Yes. Menus have no filler items and animated rank tags fall back to the plain tag.

No other plugin is required, and ProtocolLib is not used. On the first start Paper downloads a few libraries Chatalyst needs, so the server needs internet for that download.

#Folia

Chatalyst runs on Folia. These are the tests behind that claim, run on real servers on 2026-10-31 with the sale jar:

Server What was tested Result
Folia 1.21.11 build 14 45 of 55 features on, 4 players in separate regions: chat, mentions, private messages, channels, mail, reports, menus, mutes, freezes, vanish, kicks, bans, /invsee, cross-region /tpto and /tphere, /cht reload All 44 checks passed, no errors in the console
Folia 26.2 build 7 (beta) Startup, license check, /cht doctor, /cht reload, clean shutdown, with no players No errors from Chatalyst

Limits on Folia:

  • Folia does not support scoreboard teams, so the classic nametags stay off. Fancy nametags work, but the vanilla name shows behind them.
  • Not tested on Folia yet: MySQL, Redis, proxies, the Discord bot, Tebex, proximity voice and third-party integrations. Check that each plugin you use also supports Folia.

#How Chatalyst handles each message

Paper lets several plugins look at a chat message in order of priority. Chatalyst works in these steps:

Priority What Chatalyst does
LOWEST Mutes stop the message; rules block or rewrite it.
LOW Anti-spam stops repeats and flooding; grammar assist fixes the text.
NORMAL The final format is built and sent to each player.
MONITOR Mentions play their sound. Nothing is changed here.

Plugins that only read chat (loggers, Discord bridges) work fine next to it. A plugin that cancels a message earlier, for example an anti-cheat or a login plugin, stops it before Chatalyst formats it, which is what you want.

#Other chat plugins

Use one plugin to format chat. If two plugins both format each message, the last one wins and the chat looks broken or doubled. If you move to Chatalyst, remove the old chat plugin, or turn its chat formatting off (for example remove EssentialsX Chat).

If you prefer to keep another plugin for the format, you can turn Chatalyst's formatting off and keep its filters, channels and moderation:

yaml
Chat:
  Enabled: false

#Command conflicts

Two plugins sometimes register the same command, like /msg or /nick. Only one can answer.

  • Chatalyst loads before EssentialsX on purpose and takes the chat commands it provides (/msg, /nick, /me, /afk...). EssentialsX keeps all its other commands, and its own versions stay reachable as /essentials:<command>.
  • Mail is /inbox, so it never clashes with EssentialsX /mail.
  • On startup Chatalyst warns about commands that are answered by another plugin. If that is your choice, add the label to Commands_Owned_Elsewhere in config.yml and the warning stops:
yaml
Commands_Owned_Elsewhere: []

For example Commands_Owned_Elsewhere: [trade, balancetop] when another plugin handles trading and the money ranking. /cht doctor still lists them.

  • Any Chatalyst command can always be reached as /chatalyst:<command>.
  • The staff suite takes /ban, /kick and /vanish over from other plugins only while it is on (Command_Priority in moderation.yml).

#Hiding and blocking commands

Tool Setting What it does
Tab-complete filter Tab_Complete in chat.yml (on) Hides commands players should not see, such as /plugins and /version, from tab completion.
Command blocker Command_Blocker in moderation.yml (off) Blocks commands completely, whichever plugin owns them.

The command blocker ships with rules for server info, performance and world info commands:

yaml
Command_Blocker:
  Enabled: false
  Bypass_Permission: chatalyst.bypass.blocker
  Blocked:
    # Server info (plugins / version). The regex also covers namespaces like /bukkit:plugins.
    - "regex:(?i)/(\\w+:)?(plugins|pl|version|ver|about|icanhasbukkit|help|\\?)(\\s.*)?"
    # Performance / system info that could reveal setup.
    - "regex:(?i)/(\\w+:)?(timings|tps|mspt|lag|gc|memory|entities|spark|health|sysinfo)(\\s.*)?"
    # World info.
    - "regex:(?i)/(\\w+:)?(seed|datapack)(\\s.*)?"
  # Blocked for EVERYONE in game, operators and the bypass permission included: these can
  # only be run from the server console. Same entry format as Blocked. Use it for what not
  # even staff should launch from inside (e.g. "stop", "reload", "op", "deop").
  Blocked_For_Everyone: []

#Plugins Chatalyst works with

LuckPerms, Vault, PlaceholderAPI, TAB, EssentialsX, WorldGuard, Parties, ItemsAdder, Nexo, dynmap, Simple Voice Chat, Plasmo Voice, PacketEvents and Lib's Disguises are detected automatically when present. See Integrations.
