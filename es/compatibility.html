Compatibilidad y conflictos

Qué servidores y versiones soporta Chatalyst, cómo comparte el chat con otros plugins y cómo resolver los conflictos de comandos.

Esta página responde dos preguntas: si Chatalyst funcionará en tu servidor y cómo se lleva con los plugins que ya tienes. La mayoría de servidores no necesitan cambiar nada. Sigue leyendo si otro plugin también formatea el chat o usa los mismos nombres de comando.

#Servidores soportados

Soportado
Software del servidor Paper, Purpur y Folia (mira sus límites). Spigot no está soportado.
Minecraft De 1.21.1 a 26.3.
Java Java 21 para 1.21.1 a 1.21.11. Java 25 para 26.1 y posteriores.
Proxies Velocity y BungeeCord; mira Redes con proxy y Redis.
Jugadores de Bedrock (Geyser) Sí. Los menús no tienen objetos de relleno y las etiquetas de rango animadas pasan a la etiqueta fija.

No necesita ningún otro plugin y no usa ProtocolLib. En el primer arranque Paper descarga unas librerías que Chatalyst necesita, así que el servidor necesita internet para esa descarga.

#Folia

Chatalyst funciona en Folia. Estas son las pruebas que lo respaldan, hechas en servidores reales el 2026-10-31 con el jar de venta:

Servidor Qué se probó Resultado
Folia 1.21.11 build 14 45 de 55 funciones activas, 4 jugadores en regiones separadas: chat, menciones, mensajes privados, canales, correo, reportes, menús, muteos, congelar, vanish, expulsiones, baneos, /invsee, /tpto y /tphere entre regiones, /cht reload Las 44 comprobaciones pasaron, sin errores en la consola
Folia 26.2 build 7 (beta) Arranque, comprobación de licencia, /cht doctor, /cht reload y apagado limpio, sin jugadores Sin errores de Chatalyst

Límites en Folia:

  • Folia no admite los teams del scoreboard, así que los nametags clásicos se quedan apagados. Los nametags fancy funcionan, pero el nombre vanilla se ve detrás.
  • Aún sin probar en Folia: MySQL, Redis, proxies, el bot de Discord, Tebex, la voz por proximidad y las integraciones con otros plugins. Comprueba que cada plugin que uses también admita Folia.

#Cómo trata Chatalyst cada mensaje

Paper deja que varios plugins miren un mensaje de chat por orden de prioridad. Chatalyst trabaja en estos pasos:

Prioridad Qué hace Chatalyst
LOWEST Los muteos frenan el mensaje; las reglas lo bloquean o lo reescriben.
LOW El antispam frena las repeticiones y el flood; la ayuda gramatical corrige el texto.
NORMAL Se construye el formato final y se envía a cada jugador.
MONITOR Las menciones hacen sonar su aviso. Aquí no se cambia nada.

Los plugins que solo leen el chat (registros, puentes con Discord) funcionan bien a su lado. Un plugin que cancela un mensaje antes, por ejemplo un anticheat o un plugin de login, lo frena antes de que Chatalyst lo formatee, que es lo que quieres.

#Otros plugins de chat

Usa un solo plugin para formatear el chat. Si dos plugins formatean cada mensaje, gana el último y el chat sale roto o duplicado. Si te pasas a Chatalyst, quita el plugin de chat anterior o apaga su formato (por ejemplo, quita EssentialsX Chat).

Si prefieres mantener otro plugin para el formato, puedes apagar el formato de Chatalyst y quedarte con sus filtros, canales y moderación:

yaml
Chat:
  Enabled: false

#Conflictos de comandos

A veces dos plugins registran el mismo comando, como /msg o /nick. Solo uno puede responder.

  • Chatalyst carga antes que EssentialsX a propósito y se queda con los comandos de chat que ofrece (/msg, /nick, /me, /afk...). EssentialsX conserva todos sus demás comandos, y sus propias versiones siguen disponibles como /essentials:<comando>.
  • El correo es /inbox, así que nunca choca con el /mail de EssentialsX.
  • Al arrancar, Chatalyst avisa de los comandos que responde otro plugin. Si es lo que quieres, añade el nombre a Commands_Owned_Elsewhere en config.yml y el aviso deja de salir:
yaml
Commands_Owned_Elsewhere: []

Por ejemplo Commands_Owned_Elsewhere: [trade, balancetop] cuando otro plugin lleva los intercambios y el ranking de dinero. /cht doctor los sigue enseñando.

  • Cualquier comando de Chatalyst está siempre disponible como /chatalyst:<comando>.
  • La suite de staff les quita /ban, /kick y /vanish a otros plugins solo mientras está encendida (Command_Priority en moderation.yml).

#Ocultar y bloquear comandos

Herramienta Ajuste Qué hace
Filtro del tabulador Tab_Complete en chat.yml (encendido) Oculta del tabulador los comandos que los jugadores no deben ver, como /plugins y /version.
Bloqueador de comandos Command_Blocker en moderation.yml (apagado) Bloquea comandos por completo, sea cual sea el plugin dueño.

El bloqueador de comandos viene con reglas para los comandos de información del servidor, de rendimiento y del mundo:

yaml
Command_Blocker:
  Enabled: false
  Bypass_Permission: chatalyst.bypass.blocker
  Blocked:
    # Server info (plugins / version). The regex also covers namespaces like /bukkit:plugins.
    - "regex:(?i)/(\\w+:)?(plugins|pl|version|ver|about|icanhasbukkit|help|\\?)(\\s.*)?"
    # Performance / system info that could reveal setup.
    - "regex:(?i)/(\\w+:)?(timings|tps|mspt|lag|gc|memory|entities|spark|health|sysinfo)(\\s.*)?"
    # World info.
    - "regex:(?i)/(\\w+:)?(seed|datapack)(\\s.*)?"
  # Blocked for EVERYONE in game, operators and the bypass permission included: these can
  # only be run from the server console. Same entry format as Blocked. Use it for what not
  # even staff should launch from inside (e.g. "stop", "reload", "op", "deop").
  Blocked_For_Everyone: []
